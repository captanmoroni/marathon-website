# Improvement Roadmap — Marathon Guide Platform
**Goal:** transform the single-file fan page into a production-quality guide platform in the
mold of Icy Veins / Wowhead / Maxroll.

## Architecture decision
Vite + React 18 + React Router + Tailwind (built, not CDN) + lucide-react (npm).
Content lives in a versioned JSON database (`src/data/db/*.json`) with a uniform schema:
every record carries `id`, `slug`, `sources[]` (title + URL), and `lastVerified`. UI renders
from the DB only — no game facts in component code. A localStorage "draft overlay" lets the
CMS edit records in-browser and export clean JSON.

## Phases

### Phase 0 — Audit & truth pass (this document set)
- [x] Audit codebase (docs/AUDIT.md)
- [x] Research verified data with sources (docs/SOURCES.md)

### Phase 1 — Platform foundation  *(Priorities 1, 2, 3, 10)*
- Scaffold Vite app, ESLint-clean, dependency manifest
- JSON content database, all fabricated content removed/replaced with sourced data;
  anything unverifiable is labeled `unverified: true` and rendered with a visible badge
- Route hierarchy: Home · Guides index · Runner pages (8) · Faction pages (6) · Map pages (5)
  · Cryo Archive endgame guide · Build planner · News · Search · Admin (CMS)
- Global nav + breadcrumbs; every link resolves to a real page

### Phase 2 — Discovery features  *(Priorities 4, 5, 6)*
- Advanced search: tokenized inverted index over all DB records, typed filters
  (runner/faction/map/guide/news), keyboard navigation, result highlighting
- Interactive SVG maps: POI markers from DB, hover/click detail panels, layer toggles
  (loot / exfil / hazards) for Perimeter, Dire Marsh, Outpost, Night Marsh, Cryo Archive
- News ingestion: `scripts/ingest-news.mjs` pulls Bungie.net official feed at build/dev time
  into `news.json` (manual seed with sourced entries as fallback; client never fabricates news)

### Phase 3 — Publishing quality  *(Priorities 7, 8, 9)*
- CMS at `/admin`: list/edit/create records against the schema, draft overlay in localStorage,
  diff badge, JSON export for committing back to the repo
- SEO: per-route `<title>`/meta/OG/JSON-LD via a `useSEO` hook, `sitemap.xml` + `robots.txt`
  generated by `scripts/build-seo.mjs`, semantic landmarks, crawlable URLs
- Performance: route-level code splitting (`React.lazy`), prebuilt CSS, memoized search index,
  zero runtime transpilation; Lighthouse-friendly defaults

### Phase 4 — Future (not in this pass)
- Real backend (DB + auth) for community builds and comments
- Build-time prerendering/SSG for full crawler coverage
- Automated data diffing against patch notes; image/CDN pipeline; i18n
